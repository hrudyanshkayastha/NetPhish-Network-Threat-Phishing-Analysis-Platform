# NetPhish Platform Limitations & Operational Boundaries

**Author:** Hrudyansh Kayastha  
**Version:** 2.0.0  
**Classification:** Engineering Operations Specification  

---

## 1. Architectural Scope & Intent

NetPhish is purpose-built as an offline, forensic triage and evidence correlation platform. It is designed to assist security analysts, incident responders, and SOC teams in evaluating captured artifacts and host network flows deterministically. It is not intended to replace full-scale perimeter firewalls, kernel-level EDR sensors, or real-time inline packet mitigation hardware.

---

## 2. Zero-Network Execution Boundaries

1. **No Real-Time DNS Lookups:** NetPhish strictly executes offline lexical and structural domain parsing. It intentionally does not query recursive DNS resolvers or perform WHOIS queries on target domains to preserve analyst operational security (OPSEC) and prevent notifying threat actors of active investigation.
2. **No Dynamic Web Rendering:** NetPhish does not download HTML payloads, execute JavaScript runtimes, or render DOM elements. Sophisticated client-side cloaking, dynamic redirection scripts, or evasive CAPTCHA walls require sandbox emulation outside NetPhish.
3. **No Active Packet Injection:** NetPhish ingests `.pcap` and `.pcapng` capture files offline. It does not perform active network port scanning, packet injection, or man-in-the-middle decryption.

---

## 3. Heuristic & Detection Constraints

1. **Encrypted Payload Inspection (TLS/QUIC):** Network flow reconstruction operates on packet headers and transport layer metrics. NetPhish does not perform TLS decryption. Traffic traversing encrypted tunnels (such as TLS 1.3 or DoH/DNS-over-HTTPS) is evaluated via flow metadata, connection rates, timing intervals, and destination IP telemetry.
2. **Statistical Beaconing Assumptions:** The beaconing heuristic relies on inter-arrival interval regularity ($CV \le 0.35$). Advanced threat actors utilizing high-entropy jitter (e.g. randomizing sleep intervals between 10% and 50%) may circumvent static coefficient of variation thresholds.
3. **Domain Decomposition Heuristics:** NetPhish utilizes deterministic multi-part public suffix lists (`.co.uk`, `.com.au`, `.gov.uk`, etc.). Unlisted exotic multi-part country-code domains will default to single-label TLD parsing.
4. **File Size Upper Bounds:** Offline PCAP ingestion is capped at 25 MB per capture file to ensure sub-second Scapy in-memory processing on local security workstations. Enterprise captures exceeding 25 MB should be pre-filtered using `tcpdump` or `tshark` prior to submission.

---

## 4. Remediation & Operational Guidance

All risk scores and severity classifications generated by NetPhish represent automated deterministic heuristics. Security analysts should corroborate findings with enterprise endpoint logs, perimeter proxy logs, and authoritative threat intelligence feeds before taking disruptive host containment actions.
